# DESIGN.md — Дизайн-контракт `dsh-goal`

## 1. Назначение и концепция

Плагин `dsh-goal` функционирует как **расширение и надстройка (Addon)** над встроенной службой целей ядра DeepSeek Harness (`@deepseek-ai/dsh-goal`, `ctx.goals: GoalService`).

В ядре DSH (начиная с 0.1.5-rc.3 и в 0.1.7+) управление жизненным циклом цели, раунд-драйвер (`dsh-goal-round-driver`), базовые инструменты (`create_goal`, `get_goal`, `update_goal`), команда `/goal` и нативная панель `GoalBar` встроены нативно.
Плагин `dsh-goal` устраняет дублирование ядра и обогащает сессию специализированными инженерными возможностями:
1. **Бюджет токенов (Token Budget Guard)**: учёт расхода через `ctx.tokenMeter`, предупреждение при 80%, блокировка цели через нативный `ctx.goals.block(agent, ref, { code: 'budget', message })`.
2. **Этапы и чеклисты (Milestones & Checklists)**: структурированное хранение подцелей по `goalId`, собственные инструменты `goal_milestones` и `goal_checklist`, инжекция незавершённых шагов в промпт модели через `agent/pre-step`.
3. **Git-снимки этапов и откат (Snapshots & Rollback)**: автоматический коммит/снимок рабочей копии при закрытии этапа с возможностью безопасного отката из UI.
4. **Итоговые отчёты и ретроспектива**: автоматическая генерация `.dsh/goals/<timestamp>-<slug>.md` при завершении (`complete`) или очистке (`clear`) цели.
5. **Шаблоны и создание из Issue**: готовые инженерные сценарии и парсинг задач Gitea, вызывающие `ctx.goals.create(...)`.

## 2. Пользовательские поверхности (User Surfaces)

### 2.1 Нативный GoalBar ядра и Addon-интерфейс
- **Нативный GoalBar ядра (`@deepseek-ai/dsh-client-ui-goal`)**: отображает активную цель, раунды, статус (`active`, `paused`, `blocked`, `complete`) и базовое управление над полем ввода.
- **Индикатор бюджета токенов**: компактный бейдж в строке ввода или рядом с GoalBar, показывающий процент расхода токенов и переходящий в предупреждающий цвет (`var(--dsw-alias-status-warning)`) при достижении 80%.
- **Кнопка вызова Drawer этапов**: кнопка в строке инструментов/дока (🎯) для открытия панели этапов, чек-листов и снимков.

### 2.2 Drawer этапов и чеклистов (Milestones & Checklists Drawer)
- **Шапка**: Прогресс по этапам (`N из M завершено`), статус зависимостей, остаток токен-бюджета.
- **Список этапов**:
  - Карточки вех с чек-боксами подзадач;
  - Метки зависимостей (`dependsOn: ['m-1']`) и индикатор блокировки 🔒;
  - Метка создания git-снимка (`📸 snapshot: dsh-goal-snapshot/...`).
- **Снимки и откат**:
  - Список контрольных точек git по завершённым этапам;
  - Кнопка «Откатить до этого этапа» с модальным подтверждением (предупреждение о потере несохранённых изменений).

### 2.3 Settings Card (`settings.plugin.item`)
- Размещение во вкладке «Настройки → Плагины → Настройки плагинов» (`key: 'dsh-goal'`).
- Конфигурация:
  - `maxTokenBudget`: лимит токенов на цель (0 — без лимита);
  - `budgetWarningThreshold`: порог предупреждения в процентах (по умолчанию 80%);
  - `autoCheckpointOnMilestone`: создание git-снимка при завершении этапа (по умолчанию true);
  - `enableMilestoneDependencies`: топологический контроль зависимостей этапов (по умолчанию true);
  - `enableTemplatesDrawer`: доступ к библиотеке готовых шаблонов (по умолчанию true);
  - `soundScheme`: звуковая тема уведомлений (`default`, `minimal`, `retro`).

## 3. Инструменты модели (Model Tools)

Плагин **не регистрирует** инструменты `create_goal`, `get_goal`, `update_goal` (они предоставляются ядром DSH).
Плагин регистрирует собственные инструменты надстройки:

### 3.1 `goal_milestones`
- **Назначение**: Управление этапами активной цели.
- **Параметры**:
  - `action`: `'list'` | `'set'` | `'add'` | `'complete'`
  - `milestones`: массив объектов этапов `[{ id, title, checklist: [{ text, done }] }]` (для `'set'`)
  - `milestone`: объект `{ title, checklist: [...] }` (для `'add'`)
  - `milestoneId`: идентификатор этапа (для `'complete'`)
  - `notes`: заметка о результатах выполнения (для `'complete'`)

### 3.2 `goal_checklist`
- **Назначение**: Переключение состояния пунктов чек-листа конкретного этапа.
- **Параметры**:
  - `action`: `'toggle'`
  - `milestoneId`: идентификатор этапа
  - `index`: индекс пункта чек-листа (0-based)
  - `done`: булево значение (`true`/`false`)

## 4. Архитектурная интеграция с ядром

### 4.1 Взаимодействие со службой `GoalService`
1. **Событие `goal/changed`**:
   - `operation === 'create'`: инициализация хранилища этапов для нового `goal.id`, сброс счётчика токенов сессии.
   - `operation === 'complete' | 'clear'`: сохранение отчёта `.dsh/goals/<timestamp>-<slug>.md`, финализация ретроспективы.
   - `operation === 'block'`: запись причины блокировки в лог активности.
2. **Блокировка по бюджету**:
   - При превышении `maxTokenBudget` плагин вызывает:
     ```js
     ctx.goals.block(agent, currentGoalRef, {
       code: 'budget',
       message: `Token budget limit (${maxTokenBudget}) exceeded.`
     });
     ```
   - Ядро переводит цель в фазу `blocked`, GoalBar отображает причину блокировки.

### 4.2 Модельный промпт (`agent/pre-step`)
- Плагин регистрирует waterfall-слушатель `agent/pre-step`.
- Если текущая цель активна (`phase === 'active'`), в сообщения шага добавляется компактный системный контекст:
  `[Goal Milestones]: Active: "<title>" | Checklist: [x] done, [ ] pending`
- При отсутствии активной цели или её паузе/блокировке контекст не инжектируется.

## 5. Хранение данных и безопасность

- Этапы, чек-листы и метаданные снимков сохраняются в JSON-хранилище с привязкой к `goalId`.
- При откате git-снимка проверяется принадлежность пути доверенному корню сессии (confinement guard).
- Все REST-маршруты `/dsh-goal/*` защищены через `getRequestRejection` и `isTrustedCaller` с делегированием аутентификации ядру DSH (`connection.requestRejection`).

### 5.1 Сетевая модель доверия и строгая аутентификация (Fail-Closed Auth Boundary, #172)

- **Аутентификация ядра DSH (`connection.requestRejection`)**: Все запросы к маршрутам плагина (`/dsh-goal/events`, `/dsh-goal/templates`, `/dsh-goal/state`, `/dsh-goal/action`) валидируются через ядровый сервис сессий `ctx.connection.requestRejection(req)`. Запросы без валидной браузерной сессии DSH отклоняются с кодом `401 Unauthorized`.
- **Отказ от ненадёжного доверия по LAN IP (#172)**: Архитектурный компромисс, при котором запросы с LAN IP принимались лишь при наличии заголовка `Sec-Fetch-Site: same-origin` и совпадении `Origin`/`Host`, устранён как уязвимый к подделке заголовков неавторизованными локальными клиентами (`curl`, скрипты). Наличие LAN IP само по себе не является аутентификацией.
- **Fail-Closed Boundary**: Внешние (non-loopback) запросы из LAN/WAN без валидной сессии DSH или явного токена авторизации безусловно отклоняются с `401` (Unauthorized) или `403` (Forbidden), предотвращая несанкционированное чтение состояния целей и инъекции промптов (`nudge`/`resume`) в автономного агента.
- **Поддержка токена авторизации (CLI / Automation, #148, #158)**: При передаче `X-DSH-Auth-Token` или `Authorization: Bearer <token>`, совпадающего с `DSH_GOAL_AUTH_TOKEN`, запрос допускается без браузерной сессии.
- **Доверенный Loopback (Local CLI / Healthcheck, #172)**: Локальные вызовы с loopback (`127.0.0.1`, `::1`) допускаются без сессии браузера для обеспечения работы локального мониторинга, CLI и верификации развёртывания (`deploy.sh verify web`).
- **Защита от CSRF**: Запросы с заголовками `Sec-Fetch-Site: cross-site` или `same-site` безусловно отклоняются (`403 Forbidden`). Заголовки `Origin` и `Referer` (при наличии) обязаны совпадать с `Host`.
- **Защита от DNS Rebinding и WAN-трафика (#160)**: `isTrustedHost` проверяет `Host`, `remoteAddress`, `Origin` и `Referer`. Публичные WAN IP и неразрешённые внешние домены безусловно блокируются (`403 Forbidden`).
