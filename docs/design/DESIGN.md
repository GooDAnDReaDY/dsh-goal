# DESIGN.md — Дизайн-контракт `dsh-goal`

## 1. Назначение и концепция

Плагин `dsh-goal` реализует автономный режим достижения целей (Goal Mode) для **DeepSeek Harness** (DSH).
Визуальная доминанта — компактная закреплённая верхняя панель (Sticky Top Banner), отображающая текущую активную цель, секундомер выполнения и кнопки мгновенного управления (🗑 сброс, ⏸ пауза/возобновление, ⛶ детали/модалка).

---

## 2. Пользовательские поверхности (User Surfaces)

### 2.1 Sticky Top Banner (Верхняя закреплённая панель цели)
- **Расположение**: Верхняя часть окна чата/сессии над лентой сообщений.
- **Элементы слева направо**:
  1. `IconTarget` (🎯 SVG 16x16, обводка `currentColor`);
  2. Заголовок **«Текущая цель»** (вес 600, `var(--dsw-alias-label-primary)`);
  3. Текст цели (например: «привет» или «Исправить баг в аутентификации», цвет `var(--dsw-alias-label-secondary)`, `text-overflow: ellipsis`);
  4. Разделитель и таймер: `• 2s` (динамический счётчик `• 14s`, `• 2m 15s`, шрифт `monospace`);
  5. Панель кнопок справа:
     - Кнопка **🗑 (Очистить / Отменить)**: диалог подтверждения отмены/сброса цели;
     - Кнопка **⏸ / ▶ (Пауза / Продолжить)**: переключение между автономным циклом (`RUNNING`) и паузой (`PAUSED`);
     - Кнопка **⛶ (Развернуть детали)**: открытие модального окна со списком вех и логом.

### 2.2 Modal Details Dialog (Окно декомпозиции и прогресса ⛶)
- **Шапка**: Название цели, статус-бейдж (`В процессе`, `На паузе`, `Завершено`), общий процент выполнения.
- **Тело**:
  - Чеклист вех (Milestones): статус каждой вехи (`pending` ⏳, `in_progress` 🔄, `completed` ✅, `failed` ❌);
  - Лог итераций и ключевых выводов модели;
  - Метрики: общее время, количество итераций (turns), максимальный лимит.
- **Футер**: Кнопки ручного добавления шага, паузы и закрытия.

### 2.3 Settings Card (`settings.plugin.item`)
- Размещение во вкладке «Настройки → Плагины → Настройки плагинов», свёрнута по умолчанию, раскрытие по клику по заголовку (`aria-expanded`).
- Ключ слота (`key`) — пространство настроек `dsh-goal`; пока снимок пространства не в статусе `ready`, карточка не рисуется; при `writable: false` поля и кнопки заблокированы.
- Параметры (фактический набор, регистрируется schemastery-схемой):
  - `maxIterations`: максимальное число автономных шагов до принудительной остановки (дефолт: 25);
  - `autoDrive`: автоматически продолжать цикл после каждого хода (дефолт: true);
  - `enableSound`: звуковой сигнал по завершении цели (дефолт: true).
- Поля читаются из живого снимка пространства (`ctx.settingsScope.bind({ namespace })`), кнопки «Сбросить» / «Сохранить» в футере; сохраняются только изменённые поля, все записи выполняются подряд (не до первой ошибки), результат сверяется обратным чтением; неудачная запись не стирает введённые значения.
- `Changed in ядро 0.1.2-rc.1`: поле `promptTemplate` никогда не было реализовано в коде и из схемы удалено из описания; контракт карточки переехал на встроенные службы ядра (`slots` / `locale` / `settingsScope`), `dsh.client.inject` пуст.

## 3. Цветовая палитра и токены DSH

Плагин использует исключительно системные переменные DSH:
- Фоновый слой: `var(--dsw-alias-bg-layer-3)` и `var(--dsw-alias-bg-layer-2)`
- Границы: `var(--dsw-alias-border-l2)`
- Текст основной: `var(--dsw-alias-label-primary)`
- Текст вторичный: `var(--dsw-alias-label-secondary)`
- Текст третичный / метки времени: `var(--dsw-alias-label-tertiary)`
- Акцент/успех: `var(--dsw-alias-status-success)`
- Предупреждение/пауза: `var(--dsw-alias-status-warning)`
- Ошибка/удаление: `var(--dsw-alias-status-danger)`

## 4. Состояния (State Machine)

| Состояние | Баннер | Действия |
|---|---|---|
| `IDLE` | Скрыт или нейтральный placeholder | Кнопка «Поставить цель» |
| `RUNNING` | Активен, таймер тикает, индикатор мишени | 🗑 Отмена, ⏸ Пауза, ⛶ Детали |
| `PAUSED` | Активен, таймер застыл, иконка ▶ вместо ⏸ | 🗑 Отмена, ▶ Возобновить, ⛶ Детали |
| `COMPLETED` | Активен, зелёная иконка успеха, итоговое время | 🗑 Очистить, ⛶ Посмотреть отчёт |
| `FAILED` | Активен, красная иконка ошибки/лимита | 🗑 Очистить, ⛶ Логи ошибки |

## 5. Locked Design Decisions

1. **Единый префикс классов**: `.dsh-goal-*` во всех CSS-правилах во избежание конфликтов стилей.
2. **Точный макет баннера**: скругление углов 8–10px, шапка с отступами `8px 16px`, выравнивание по центру, кнопки действий справа с `gap: 10px`.
3. **Безопасность импортов**: все `require('@deepseek-ai/dsh-client-ui-primitives')` обёрнуты в `try/catch` с SVG-фоллбеками.
4. **2026-09-04 — rc.1-совместимость клиента**: `dsh.client.inject: []` — в boot-графе клиента ядра 0.1.2-rc.1 нет package-строк `dsh-client-runtime` (модуля в ядре нет вовсе) и `dsh-client-ui-slots`; `slots`/`locale`/`settingsScope` — встроенные службы ядра. `react`, `@deepseek-ai/dsh-client-ui-slots`, `@deepseek-ai/dsh-client-ui-primitives` отвечаются статической seed-таблицей шелла, но динамических package-строк под них в boot-графе нет — объявлять их в inject нельзя. Условие пересмотра: появление этих package-строк в boot-таблице ядра.
5. **2026-09-04 — контракт карточки настроек**: key слота = пространство настроек (`dsh-goal`), чтение через `ctx.settingsScope.bind`, решение по статусу снимка (loading/unavailable/ready + writable), сохранение всех изменённых полей с обратной сверкой. Причина: контракт вкладки «Настройки → Плагины» ядра rc.1 (BashCard/AgentLoopCard как эталон). Пересмотр — при изменении контракта слота в ядре.

6. **2026-09-10 — унификация дизайн-системы с dsh-clinebot (v0.1.5)**:
   - Приведение кнопок, плашек и статусов к единому стилю: овальные пилюли (`.dsh-goal-badge`), кнопки с радиусом 8px, hover-состояниями и цветами (`.dsh-goal-btn-primary`, `.dsh-goal-btn-danger`).
   - Модальное окно декомпозиции цели обогащено компактным 3-колоночным гридом метрик (`.dsh-goal-stat-grid`, `.dsh-goal-stat-box`).
   - Инъекция стилей в DOM изолирована атрибутом `data-dsh-plugin="dsh-goal"`.
   - Серверная защита REST API: ограничение размера тела запроса до 256 КБ (413 Payload Too Large) и строгая валидация входящих параметров вех.
   - Ограничение сессионной памяти: автоматическая ротация завершённых неактивных сессий в `GoalEngine.pruneInactiveSessions()`.

7. **2026-09-12 — Realtime SSE, Low-Latency AutoDrive, Smart Progress Guard, Crash Hydration и Web Audio (v0.1.6)**:
   - **Realtime Server-Sent Events (`GET /dsh-goal/events`)**: Стриминг снимков состояния цели клиенту в реальном времени с периодическим keepalive-пингом (20s). Устраняет сетевую задержку поллинга при выполнении итераций.
   - **Адаптивный fallback-поллинг**: При сбое SSE соединения клиент бесшовно переключается на адаптивный поллинг (1.5s при RUNNING, 8s при простое).
   - **Low-Latency AutoDrive**: Замена статического `setTimeout(..., 300)` на микрозадачу/`setImmediate` в координаторе `onTurnEnd` для устранения искусственных задержек между шагами автономного цикла.
   - **Smart Progress Guard**: Детекция застрявшего цикла агента (2 последовательных холостых хода без изменения/добавления вех) с автоматической паузой и фиксацией причины в логах во избежание перерасхода токенов.
   - **Crash Hydration**: При перезапуске DSH цели, оставшиеся в статусе `RUNNING`, автоматически гидрируются в `PAUSED` с отметкой времени и пояснением оператору для ручного возобновления в 1 клик.
   - **Web Audio Синтез**: Синтезированные пентатонические колокольчики через `window.AudioContext` при завершении цели (`COMPLETED` — мажорный аккорд, `FAILED` — минорный аккорд) с соблюдением настройки `enableSound`.
   - **Milestone Integrity**: Статус выполнения вех строго контролируется агентом; чекбоксы ручной отметки в UI исключены в соответствии с архитектурным контрактом.

8. **2026-09-12 — Сессионная изоляция /goal, устойчивость SSE и строгая REST валидация (v0.1.7)**:
   - **Сквозная сессионная изоляция в слеш-команде**: В `command-handler.js` метод `executeGoalSlashCommand` пробрасывает `sessionId` во все вызовы `engine` (`getSnapshot`, `startGoal`, `pause`, `resume`, `clear`), исключая мутацию глобальной сессии при работе в конкретном чате.
   - **Устойчивость SSE с Exponential Backoff**: На клиенте внедрена автоматическая схема повторного подключения `EventSource` с возрастающей задержкой (от 2s до 30s) и рандомизированным джиттером для защиты от шторма переподключений.
   - **Строгая REST валидация и Enum Guard**: Обработчик `POST /dsh-goal/action` валидирует непустой `title` при старте цели и проверяет допустимость статуса вехи по `MilestoneStatus` enum, возвращая внятный HTTP 400 Bad Request / 404 Not Found.
   - **Безопасность файловой системы**: `GoalEngine.writeStateToDiskSync()` гарантированно создаёт отсутствующие родительские директории через `fs.mkdirSync(dir, { recursive: true })` перед созданием временного файла и атомарным переименованием.

### Решение 9: Интеллектуальная оценка времени (ETA), аналитика токенов, кнопка быстрого запуска цели и экспорт отчетов в Markdown

**Контекст:**
После стабилизации сессионной изоляции и SSE-потока пользователям требовалась наглядная оценка оставшегося времени работы над целью, понимание расхода токенов за цикл, удобный запуск цели без ручного ввода команды `/goal` и возможность мгновенно экспортировать структурированный итоговый отчёт в markdown-формате.

**Принятые решения:**
1. **Расчет оставшегося времени (ETA projection):**
   - Метод `getEstimatedRemainingSeconds(sid)` рассчитывает среднее время на выполнение завершенных вех `elapsed / completedCount` и умножает на количество оставшихся шагов.
   - В верхнем баннере и модальном окне отображается живое время работы с прогнозом: `⏱ 45s (ETA ~2m)`.
2. **Аналитика расхода токенов (Token Usage Analytics):**
   - Накопление счетчиков `promptTokens`, `completionTokens`, `totalTokens` на каждом завершении хода `turn/end` через `engine.addTokenUsage(usage, sid)`.
   - В модальном окне деталей в сетку характеристик добавлен блок «Токены» с подсказкой при наведении с детальным расщеплением.
3. **Кнопка быстрого запуска цели (Quick Launch button):**
   - Когда цель не активна, в `conversation.input.dock` отображается компактная кнопка с иконкой 🎯.
   - По клику открывается модальное окно с полем ввода для немедленной постановки задачи агенту без ручного ввода слэш-команд.
   - В карточке настроек добавлен переключатель `showQuickLaunchButton` с возможностью сброса к дефолту.
4. **Экспорт отчета в Markdown (One-click Markdown Export):**
   - Для выполненной цели модальное окно предоставляет кнопку «📋 Скопировать отчёт в Markdown».
   - Генерирует отчет с заголовком, статусом, длительностью, итерациями, расходом токенов, резюме результатов и таблицей вех.

### Решение 10: Бесшовная совместимость и перехват базовых инструментов целей DSH (update_goal, get_goal, create_goal) (v0.1.10)

**Контекст:**
В GitHub Issue #2 пользователи столкнулись с ошибкой:
`complete and blocked require a direct human turn or the current goal round`
при попытке модели завершить или обновить цель вызовом встроенного инструмента `update_goal`.
Причина: встроенный плагин ядра DSH (`@deepseek-ai/dsh-tool-goal`) накладывает жёсткие проверки происхождения хода (authority checks), которые дают сбой в автономных циклах и при вызовах вне строго размеченного раунда цели.

**Принятые решения:**
1. **Динамическое замещение инструментов ядра в `ToolRuntime`:**
   - При инициализации `ctx.inject(['tools'], (tctx) => { ... })` плагин проверяет наличие `update_goal`, `get_goal`, `create_goal` в глобальном слое (`tctx.tools.layers.global.tools.data`), удаляет конфликтующие строгие определения ядра и регистрирует собственные полнофункциональные версии.
2. **Маршрутизация действий в `GoalEngine`:**
   - `update_goal` перехватывает все действия модели:
     - `action: 'complete'` — завершает цель в `engine.completeGoal()`, внедряет заключительный контекст `<goal_complete>` и возвращает статус `complete`;
     - `action: 'pause'` — переводит цель в паузу через `engine.pause()`;
     - `action: 'resume'` — возобновляет цель (`engine.resume()`) и перезапускает автодрайв агента;
     - `action: 'edit'` — обновляет цель (`title`) и лимит раундов (`maxIterations`);
     - `action: 'blocked'` — фиксирует блокер в `engine.pause()` с возвратом фазы `blocked` и кода причины.
3. **Строгое соответствие схеме `GOAL_OUTPUT`:**
   - Все перехваченные инструменты возвращают структуры, валидные по спецификации `GOAL_VALUE_SCHEMA` ядра (`goal: null` при отсутствии активной цели, либо объект цели с `id`, `revision`, `objective`, `phase`, `roundsStarted`, `maxGoalRounds`, `activation`).
4. **Нейтрализация устаревшего системного промпта ядра:**
   - Удаляется секция `tool:goal` ядра с ошибочными директивами и заменяется актуальной динамической инструкцией `tool:dsh-goal`.


### Решение 11: Живая корректировка цели (Live Steering / Nudge), браузерные уведомления, 10 инженерных пресетов, защита от сбоев инструментов и Git Checkpoints (v0.2.0)

**Контекст:**
В процессе активной эксплуатации автономного режима Goal Mode пользователям требовались:
1. Возможность вносить точечные корректировки и уточнения в активную или приостановленную цель без прерывания сессии или перезапуска;
2. Получение нативных уведомлений операционной системы при завершении длительных фоновых задач;
3. Быстрый выбор типовых инженерных задач (багфикс, рефакторинг, тесты, код-ревью и др.) без ручного набора стандартных промптов;
4. Защита от бесконечных повторных вызовов падающих инструментов (Tool-Failure Breaker) с настраиваемым порогом;
5. Фиксация точки старта в репозитории (Git Checkpoint) для моментального просмотра изменений и отката;
6. Экспорт структурированного отчета с интерактивными спойлерами для комментариев в GitHub / Gitea PR.

**Принятые решения:**
1. **Live Steering / Nudge**:
   - Реализован метод `engine.nudge(text, sid)` и эндпоинт `POST /dsh-goal/action` с `action: 'nudge'`.
   - Поле ввода в модальном окне деталей позволяет оператору направить агента.
   - Указание сохраняется в `goal.nudges` и инжектируется в следующий промпт автодрайва как высокоприоритетная директива `🚨 URGENT USER CLARIFICATION / STEERING`.
2. **Нативные браузерные уведомления (Notification API)**:
   - При завершении цели (`COMPLETED` или `FAILED`) клиент вызывает системный push через `new Notification(...)` при наличии разрешения.
   - В карточке настроек добавлен чекбокс `enableBrowserNotifications` с интерактивным запросом прав.
3. **10 инженерных шаблонов запуска (Quick Launch Presets)**:
   - В окно быстрого запуска добавлена лента чипов с 10 сценариями на трёх языках (`en`, `ru`, `zh`):
     1. 🐛 Fix Bug & Verify
     2. ⚡ Refactor (YAGNI)
     3. 📝 Tests & Coverage
     4. 🔍 Code Review
     5. 🚀 New Feature
     6. 🛡️ Security Audit
     7. 📚 Docs & Contract
     8. 📦 Upgrade Deps
     9. 🧹 Dead Code Cleanup
     10. ⚙️ Performance
4. **Защита от циклических сбоев инструментов (Tool-Failure Breaker)**:
   - В `GoalEngine` внедрен счетчик последовательных ошибок инструментов (`consecutiveToolFailureLimit`, по умолчанию 3, 0 — отключено).
   - При превышении порога цель автоматически переводится в `PAUSED` с фиксацией точной причины в журнале.
   - Порог настраивается через Schemastery карточку в интерфейсе настроек.
5. **Git Checkpoint Snapshot**:
   - При старте цели через `node:child_process` фиксируется короткий хеш `git rev-parse --short HEAD` (с таймаутом 1 сек).
   - В окне деталей отображается бейдж `📌 Git: <commit>` с копированием команды `git diff <commit>` в один клик.
6. **Экспорт отчета для GitHub / Gitea PR**:
   - Метод `exportReportGitHubPR(state)` форматирует статус, время, расход токенов, резюме и таблицу вех внутри сворачиваемого блока `<details><summary>`.
   - В окне деталей добавлена кнопка «🐙 Копировать для GitHub PR».

## 6. Архитектурные контракты и решения обслуживания (v0.2.3)

### 6.1 Контракт внедрения зависимостей клиента (dsh.client.inject: [], Issue #57)
В package.json сохраняется пустое поле dsh.client.inject: [] для полной обратной совместимости с загрузчиком DSH rc.1. Это предотвращает ошибочные попытки устаревших загрузчиков внедрять неактуальные зависимости rc.0. Внутри клиентского модуля точный список зависимостей декларируется нативно через module.exports.inject = ['slots', 'locale', 'settingsScope'].

### 6.2 Архитектура клиентского бандла (lib/client.js, Issue #54)
В соответствии со стандартом dsh-plugin-authoring (строки 611-625), код клиентской части выполняется непосредственно в браузере через загрузчик window.__ModuleLoader__.load({ id, factory }) без отдельного шага сборки (Webpack/Vite). Для сохранения максимальной надёжности и независимости рантайма клиентский компонент поддерживается единым файлом lib/client.js. Вся серверная половина плагина полностью декомпозирована на модули размером менее 600 строк (lib/index.js, lib/routes.js, lib/tools.js, lib/goal-engine.js, lib/updater.js, lib/engine-store.js, lib/engine-reports.js, lib/goal-engine-constants.js, lib/command-handler.js, lib/engine-prompt.js).

### 6.3 Строгий контракт интернационализации (Issue #48)
Внутри файлов плагина (lib/*.js) полностью исключены хардкод русских строк, комментариев и ветвлений вида lang === 'ru'. Ядро плагина поддерживает только канонический английский (n) как базовый язык и китайский (zh) как обязательную пользовательскую локаль. Полная русская локализация интерфейса и сообщений предоставляется системным плагином @goodandready/dsh-russian-lang. Соблюдение правила контролируется автоматическим регрессионным тестом 	est/i18n-locale.test.mjs.

### 6.4 Автообновление в один клик (Issue #49)
Реализован независимый модуль автообновления lib/updater.js, зарегистрированный по маршруту /api/dsh-goal/update. Маршрут защищён проверкой локального источника (loopback origin) и не использует запрещённый флаг --config.minimumReleaseAge=0.

### 6.5 Защита статуса настроек (Issue #50)
В карточке настроек устранено ложное отображение статуса 'ready' при отсутствующем или ещё не загруженном объекте снимка настроек (settingsScope). При отсутствии снимка возвращается 'unavailable' или 'loading'.

### 6.6 Токены дизайн-системы и изоляция стилей (Issue #52, #53)
Все цвета и тени переведены на стандартные переменные дизайн-системы DSH (--dsw-alias-*), исключены любые автономные объявления 
gba(...). Чужеродный CSS-класс cb-badge-ok заменён на нативный селектор плагина dsh-goal-badge-ok.

### 6.7 Надёжность и обработка исключений (Issue #58)
Устранены все пустые блоки catch (_) {}. Добавлено контекстное логирование ошибок в deferred-контекстах <goal_complete> и <goal_blocked>. Реализована автоматическая очистка мёртвых соединений клиентов в SSE-потоках (/dsh-goal/events).

## 7. Power Suite (v0.2.6)

### 7.1 Компактный режим панели (Compact Dock Mode)
- **Концепция**: Для экономии экранного пространства над полем ввода пользователь может свернуть закреплённую панель цели (`GoalTopBanner`) в аккуратную капсулу (Status Pill).
- **Элементы капсулы**:
  - Иконка 🎯 `IconTarget`;
  - Название цели с обрезкой (`text-overflow: ellipsis`);
  - Счётчик этапов (например, `[2/4]`);
  - Кнопка разворачивания (`IconMinimize` / `IconMaximize`).
- **Персистентность**: Состояние сворачивания сохраняется в браузере через `localStorage.getItem('dsh_goal_dock_collapsed')`.

### 7.2 Подзадачи и интерактивные чек-листы (Sub-milestones & Checklists)
- **Структура**: Каждый этап `milestone` может содержать массив подзадач `checklist: [{ text: string, done: boolean }]`.
- **Интерактивность**:
  - Пользователь может кликать по чекбоксам в модальном окне деталей для мгновенной отметки выполнения (отправляет POST `toggle_checklist_item`);
  - Модель может передавать список подзадач в инструменте `goal_update_progress`;
  - В системный промпт модели подзадачи инжектируются в формате `  - [x] Выполнено` / `  - [ ] В процессе`.

### 7.3 Token Budget Guard (Контроль расхода токенов)
- **Параметры**:
  - `maxTokenBudget` (число, по умолчанию `0` — выключено);
  - `budgetWarningThreshold` (процент, по умолчанию `80`%).
- **Поведение**:
  - При достижении `budgetWarningThreshold` (80% бюджета) в системный промпт внедряется предупреждение с просьбой оптимизировать вызовы инструментов и завершить этап;
  - При 100% расхода цель мягко приостанавливается со статусом `PAUSED_BUDGET_EXCEEDED` (не прерывая сессию принудительно);
  - В баннере и модалке появляется кнопка мгновенного продления бюджета (`+50,000 токенов`) в один клик.

### 7.4 Автоматические Git-чекпоинты (Auto Git Checkpoints)
- **Параметр**: `autoCheckpointOnMilestone` (boolean, по умолчанию `false`).
- **Поведение**:
  - При успешном завершении этапа (`COMPLETED`) плагин автоматически создаёт коммит вида `chore(goal): checkpoint [milestone-title]`;
  - Хэш коммита сохраняется в поле `checkpointCommit` этапа;
  - В модальном окне деталей отображается хэш коммита и кнопка отката (Rollback), вызывающая безопасный `git reset --hard <hash>`.

### 7.5 Экспорт артефактов выполнения (Run Artifact Export)
- **Функционал**: Сохранение полного Markdown-отчёта о выполнении цели в локальный файл `.dsh/goals/<timestamp>-<slug>.md`.
- **Каталог**: Директория `.dsh/` добавлена в корневой `.gitignore`, предотвращая случайное попадание локальных артефактов в репозиторий.
- **Доступ**: Кнопка «Сохранить артефакт» в модальном окне деталей запускает сохранение и возвращает локальный путь к файлу.

### 7.6 Безопасность и архитектурные инварианты (v0.2.7)
- **Модульная декомпозиция движка**: Вспомогательная логика вех и чеклистов вынесена в `lib/engine-milestones.js`, гарантируя соблюдение порога < 600 строк в `lib/goal-engine.js`.
- **Строгая валидация рабочего каталога**: Все эндпоинты, принимающие `cwd` (`save_artifact`, `rollback_milestone`), проверяют физическое существование каталога и возвращают HTTP 400 при некорректных путях.
- **Прямое выполнение git без шелла**: Все вызовы `git` выполняются через `execFileSync` без порождения `/bin/sh`.
- **Корректный HMR-жизненный цикл**: Регистрации клиентских слотов и локалей изолированы внутри `ctx.effect`, предотвращая утечки обработчиков при перезагрузке веб-интерфейса.
